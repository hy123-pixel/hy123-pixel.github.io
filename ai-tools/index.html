让 AI 真正做事：工具调用的设计方法

模型负责理解与决策，工具负责访问真实世界；把两者的边界设计好，Agent 才不至于失控。

工具调用解决什么问题

语言模型无法直接查询你的订单、读取数据库或发送通知。工具调用把这些能力描述成结构化函数：模型决定“是否调用”与“传什么参数”，程序则负责真正执行并返回结果。

工具定义要比 Prompt 更严格

每个工具都要写清名称、用途、参数类型、必填字段与失败时的返回。参数校验应在服务端完成，不能指望模型永远传对数据。

权限原则：只读工具可以自动执行；凡是会修改数据、发送消息或产生费用的工具，默认都需要二次确认。

一个安全的执行闭环

模型提出调用 → 程序校验参数 → 权限层判断 → 工具执行 → 记录审计日志 → 模型解释结果。任一步骤失败，都应返回可理解的错误，而不是让模型凭空编造答案。

从只读工具开始

  • 先做天气、文档检索、数据库查询等无副作用工具。
  • 为每次调用设置超时、重试次数和最大循环数。
  • 对敏感操作增加人工确认，并保证重复执行不会造成重复扣款或重复发送。

Agent 的“聪明”只是入口，真正决定体验的是工具边界、权限与可追溯性。
