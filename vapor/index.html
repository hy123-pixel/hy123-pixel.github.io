Vapor 从 0 开始：用 Swift 写后端与网站

Vapor 是一个用纯 Swift 编写的服务端框架，底层基于苹果的非阻塞网络库 SwiftNIO。你可以用同一门语言同时包揽 iOS 客户端与后端，复用数据模型，不必在语言之间来回切换。下面这组文章从环境搭建讲起，依次覆盖路由、控制器、网页渲染、数据库、用户认证与上线部署，带你把一个真实的 Vapor 应用完整跑通。

版本说明：本系列示例主要对应 Vapor 4（当前主版本），个别段落保留了 Vapor 3 的写法以作对照。Vapor 3 与 4 的核心思想一致，主要是 API 命名变化（如用 Application / req.db 取代旧版的 drop / req 上的 Fluent 方法）。内容整理参考自 vapor.jokerhub.cn 的《Vapor 大型教程》。

Vapor 是什么，为什么值得学

Vapor 是 2016 年由 Tanner Nelson 发起、后并入 Swift Server Group 的框架，主打「纯 Swift 实现、简洁、社区活跃」。它基于苹果的 SwiftNIO——一个非阻塞的网络库，因此天然适合高并发的服务端场景。

用 Swift 写服务端的好处

  • 强静态类型：编译期就拦掉一大批错误，减少运行期崩溃。
  • 编译型语言：性能普遍好于解释型脚本语言。
  • 前后端同语言：iOS 开发者能包揽两端，不换语言、复用模型。
  • 完善工具链：Swift + Xcode 自带成熟的 IDE 与调试能力。

用 Vapor 开发的好处

  • 前后端同语言：数据层模型可直接复用，降低切换成本。
  • Codable 加持：JSON 与模型互转的代码量极少。
  • 完全非阻塞：请求未立即返回时先放一边处理别的，吞吐更高。

怎么把 Vapor 学扎实

原教程作者总结的学习路径只有三步，核心就是动手写代码：

  • 看教程，写代码——照着示例把每个接口都跑一遍。
  • 看文档，写代码——遇到问题查官方文档，而不是只会复制粘贴。
  • 看源码，写代码——读 Vapor 和 Fluent 的源码，理解它为什么这么设计。

Vapor 的魅力在于「简单」：一门 Swift，前后端通吃，Codable 和 Fluent 帮你省掉大量样板代码，SwiftNIO 又给了你不输其他语言的并发能力。上面 7 篇就是一份可跟着敲的地图——选一个最小可用的点子，先让它在 localhost 上跑通，再一步步加功能、接数据库、上线。写代码，永远比看代码学得快。
