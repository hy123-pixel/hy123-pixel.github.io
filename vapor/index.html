Vapor 从0开始：用 Swift 写后端与网站的完整教程

Vapor 是一个用纯 Swift 编写的服务端框架，底层基于苹果的非阻塞网络库 SwiftNIO。你可以用同一门语言包揽 iOS 客户端和后端，复用数据模型、告别语言切换。本文从环境搭建一直讲到第一个路由、数据库增删改查、网页渲染、用户登录和上线部署，带你把一个真实的 Vapor 应用跑通。

版本说明：本文内容整理自 vapor.jokerhub.cn 的《Vapor 大型教程》，示例代码主要对应 Vapor 3（SwiftNIO 时代），其中路由片段也出现了 Vapor 4 风格的写法（原始教程如此）。Vapor 目前主版本为 4，API 有变化（如用 Application 取代 router/services、异步改用 async/await），但核心概念完全一致。正式项目请以你安装的 Vapor 版本官方文档为准，本文侧重讲清思路。

一、什么是 Vapor

Vapor 是一个用 Swift 语言 写的开源框架，基于苹果的 SwiftNIO 库。它可以用来构建两类东西：后端服务和 Web 网页。

2016 年 1 月，Tanner Nelson 启动了 Vapor 项目，随后 Logan Wright 加入。因为 Vapor 使用了 Swift 风格的 API 和大量语言特性，很快在 GitHub 上成为流行的服务端 Swift 框架，并随着 Swift 开源被并入 Swift Server Group，成为苹果官方支持的服务端开发框架。

它主要由几个组件构成：

  • Leaf：开发前端页面使用的模板语言，用来把数据渲染成 HTML。
  • Fluent：用 Swift 写的对象关系映射（ORM）框架，让你用 Swift 类型操作数据库，而不用手写 SQL。
为什么偏偏选 Vapor？作者给出的理由是：官网简洁、框架用纯 Swift 实现、社区活跃、项目规模不大——对于不需要太复杂功能的开发者刚好。简单的东西总是让人喜欢。

二、为什么用 Swift 写服务端

很多服务端语言是解释型的，而 Swift 是编译型语言。用 Swift 做服务端开发有几个很实在的好处：

  • 强静态类型：编译期就能拦住大量类型错误，减少应用运行期的崩溃。
  • 编译型语言：执行性能优于解释型语言。
  • 前后端同一门语言：iOS 开发用 Swift，Vapor 也用 Swift，写服务端和客户端时可以复用同一套数据层模型，省去语言切换成本，扩展全栈能力。
  • Codable 协议：Vapor 大量使用 Codable，能大幅减少数据在「模型 ↔ 数据库 / 接口」之间转换格式的相关代码。
  • 非阻塞架构：Vapor 用 SwiftNIO 实现了完全非阻塞的架构。阻塞式架构里，若一次请求的中间处理很耗时，返回就会被延迟；用多线程则线程切换开销大。非阻塞架构中，如果一个请求不能马上返回，会被先放在一边，这段时间还能处理其他请求。

三、搭建开发环境

Vapor 的开发环境主要在 macOS 和 Ubuntu 两个平台上部署。核心前提是先装好 Swift（Vapor 4 要求 Swift 5.2 及以上）。

macOS

借助 Xcode 这个 IDE 开发最顺手，Xcode 内置了 Swift 环境。先确认版本：

swift --version

再装 Homebrew 包管理器，然后用它安装 Vapor 开发工具：

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install vapor

验证是否安装成功：

vapor --help

Ubuntu

Ubuntu 上还没有对 Swift 支持特别好的 IDE，可以走两条路：一是浏览 Swift 官网 按官方指引下载工具链；二是从源码安装 Vapor 工具箱：

git clone https://github.com/vapor/toolbox.git
cd toolbox
git checkout <desired version>
make install

日常开发可用 Visual Studio Code 安装 sswg.swift-lang 插件，或用 Vim。执行完上面的步骤，Vapor 的开发环境就布置完成了。

小技巧：在 macOS 上，进入 Vapor 项目根目录运行 vapor xcode（或 open Package.swift），就能用 Xcode 打开整个工程进行开发、运行和调试。

四、第一个项目：Hello Vapor

环境就绪后，用工具箱创建一个模板工程：

vapor new HelloVapor

进入目录并打开 Xcode：

cd HelloVapor
vapor xcode

运行方式有两种：命令行 vapor run，或直接在 Xcode 里点运行。项目启动后默认监听 localhost:8080。真正建立「请求 URL ↔ 处理函数」对应关系的地方，是工程里的 routes.swift 文件。

五、路由（Route）到底是什么

当浏览器向服务器发起请求时，服务器需要知道「该调用哪段代码来处理」。我们把客户请求（通常是一个 URL）和应用程序针对它进行处理的代码逻辑（通常是一个函数）之间的对应关系叫作 route（路由）。routes.swift 里做的事，就是建立这种对应关系。

下面在 routes.swift 中添加几个 GET 类型的路由：

import Vapor

func routes(_ app: Application) throws {
    app.get { req in
        return "It works!"
    }
    app.get("hello") { req -> String in
        return "Hello, world!"
    }
    app.get("hello", ":name") { req -> String in
        guard let name = req.parameters.get("name", as: String.self) else {
            return "\(HTTPStatus.notFound)"
        }
        return "Hello, \(name)"
    }
}

这三个路由分别匹配：

  • / → 返回 It works!
  • /hello → 返回 Hello, world!
  • /hello/小明 → :name 是命名占位符，会取出路径中的值，返回 Hello, 小明
如果是在 Linux 上开发，可以用自己喜欢的编辑器改文件，再用命令行 swift build 和 vapor run 编译运行；在 Mac 上则直接用 Xcode 开发更省心。

六、用控制器组织路由

项目一大，一条条手写 router 既难写也难维护。Web 开发里流行的做法是 MVC：数据库里的数据结构是 Model（模型），展示给用户的 HTML 是 View（视图），控制数据如何展示到页面的逻辑是 Controller（控制器）。Vapor 用控制器把零散的路由组织成独立模块。

控制器继承自 RouteCollection，在 boot() 里注册自己的路由，routes.swift 只负责把控制器挂上去：

import Vapor

public func routes(_ router: Router) throws {
    let acronymsController = AcronymsController()
    try router.register(collection: acronymsController)
}

控制器本体把一组相关的路由收拢到一起：

import Vapor
import Fluent

struct AcronymsController: RouteCollection {
    func boot(router: Router) throws {
        router.post("api", "acronyms", use: createHandler)
    }
    func createHandler(_ req: Request) throws -> Future<Acronym> {
        return try req.content.decode(Acronym.self)
            .flatMap(to: Acronym.self) { (acronym) in
                return acronym.save(on: req)
            }
    }
}

当控制器里多条路由共享同一个前缀（比如都挂在 api/acronyms 下）时，用 RouteGroup 更省事，避免每一条都写全路径：

func boot(router: Router) throws {
    let routeGroup = router.grouped("api", "acronyms")
    routeGroup.post(use: createHandler)
    routeGroup.get(use: getAllHandler)
    routeGroup.get(Acronym.parameter, use: getHandler)
}

七、用 Leaf 渲染网页

前面的接口返回的是纯文本或 JSON。如果要给用户看真正的网页，Vapor 提供了 Leaf 模板语言：它允许你往页面传变量，再动态生成最终 HTML，还能在页面间复用代码块。

先在 Package.swift 里加上 Leaf 依赖，然后新建 Resources/Views 目录存放模板。接着写一个专门返回网页的控制器：

import Vapor
import Leaf

struct WebsiteController: RouteCollection {
    func boot(router: Router) throws {
        router.get(use: indexHandler)
    }
    func indexHandler(_ req: Request) throws -> Future<View> {
        return try req.view().render("index")
    }
}

在 routes.swift 里注册这个控制器，并在 configure.swift 中把 Leaf 配置为一种服务：

try services.register(LeafProvider())
config.prefer(LeafRenderer.self, for: ViewRenderer.self)

Leaf 用 #(arg) 的方式把参数注入模板。控制器里通常定义一个遵循 Encodable 的上下文结构体来传数据：

struct IndexContext: Encodable {
    let title: String
}

对应的 Resources/Views/index.leaf 模板里这样用：

<title>#(title) | Acronyms</title>

八、数据库与 Fluent ORM

Vapor 原生提供了三种数据库驱动：SQLite、MySQL、PostgreSQL。数据库分关系型（SQL）和非关系型（NoSQL）两类，Vapor 目前只支持关系型数据库。

  • SQLite：基于文件的轻量关系型数据库，适合原型与测试，但不适合大量写入或跨服务器。
  • MySQL：流行于 LAMP 栈，易用且被多数云厂商支持。
  • PostgreSQL：面向商用的开源关系库，扩展性与标准化是核心目标。

本地用 Docker 跑 MySQL / PostgreSQL 很方便（它不同于虚拟机，更轻量）。为了最快跑通，开发期推荐先用 SQLite（数据直接存在本地文件）。在 configure.swift 里注册即可：

try services.register(FluentSQLiteProvider())

let sqlite = try SQLiteDatabase(storage: .file(path: "db.sqlite"))
var databases = DatabasesConfig()
databases.add(database: sqlite, as: .sqlite)
services.register(databases)

var migrations = MigrationConfig()
migrations.add(model: Acronym.self, database: .sqlite)
services.register(migrations)
只使用 SQLite 可以极大简化数据库配置，非常适合原型开发期；等要上生产时再换成 MySQL 或 PostgreSQL（配合 Docker）即可。

九、RESTful CRUD 接口

RESTful API 的做法是：用一个 URL 对应一个数据模型，再配合不同的 HTTP 方法（Method）来执行相应的增删改查（CRUD）操作。以 /api/acronyms 为例：

操作方法 + URL含义
Create 新增POST /api/acronyms创建一个新的缩略语
Retrieve 列表GET /api/acronyms获取所有缩略语
Retrieve 详情GET /api/acronyms/<ID>获取指定 ID 的缩略语
Update 更新PUT /api/acronyms/<ID>更新指定 ID 的缩略语
Delete 删除DELETE /api/acronyms/<ID>删除指定 ID 的缩略语

新增（Create）就是把请求体解码成模型后保存：

router.post("api", "acronyms") { (req) -> Future<Acronym> in
    return try req.content.decode(Acronym.self)
        .flatMap(to: Acronym.self) { (acronym) in
            return acronym.save(on: req)
        }
}

按 ID 查询（Retrieve）需要数据模型遵循 Parameter 协议：

extension Acronym: Parameter {}

router.get("api", "acronyms", Acronym.parameter) { (req) -> Future<Acronym> in
    return try req.parameters.next(Acronym.self)
}

更新（Update）则是先取出旧记录、再合并新字段后保存：

router.put("api", "acronyms", Acronym.parameter) { (req) -> Future<Acronym> in
    return try flatMap(to: Acronym.self,
                       req.parameters.next(Acronym.self),
                       req.content.decode(Acronym.self)) { (acronym, update) in
        acronym.name = update.name
        // ...合并其它字段
        return acronym.save(on: req)
    }
}

十、用户认证

认证（Authentication）是验证「你是谁」的过程，和授权（Authorization）「你能做什么」不同。最常见的是用「用户名 + 密码」组合。

密码绝不能以明文存储。Vapor 提供了工业级的 BCrypt 算法对密码做哈希：哈希是单向的，从哈希值几乎不可能反推出明文，而且 BCrypt 会自动加盐。所以在创建用户时，要先哈希再存：

import Crypto

func createHandler(_ req: Request, user: User) throws -> Future<User> {
    user.password = try BCrypt.hash(user.password)
    return user.save(on: req)
}

另外，登录时要靠「用户名 + 密码」唯一定位用户，所以用户名必须唯一。在迁移里加唯一约束：

extension User: Migration {
    static func prepare(on conn: PostgreSQLConnection) -> Future<Void> {
        return Database.create(self, on: conn) { (builder) in
            try addProperties(to: builder)
            builder.unique(on: \.username)
        }
    }
}
加了字段或约束后，需要重置一次数据库让变动生效（在 Xcode 的 Scheme 设置里加运行时参数即可）。

十一、部署到自己的云服务器

除了官方的 Vapor Cloud，你也可以把项目部署到自己买的云服务器上。思路是：在 Ubuntu 上装 Docker，用 Docker 起一个数据库容器，再运行 Vapor 应用。

docker run --name postgres \
  -e POSTGRES_DB=vapor \
  -e POSTGRES_USER=vapor \
  -e POSTGRES_PASSWORD=password \
  -p 5432:5432 \
  -d postgres

然后启动应用，并让它监听所有网卡：

vapor run --hostname=0.0.0.0 --port=8080

最后记得在云服务器控制台开放端口、配置域名解析，并用 nginx 做端口转发（把 80/443 转发到 8080）。这样外界就能通过域名访问你的 API 了。

十二、怎么把 Vapor 学扎实

原教程作者总结的学习路径只有三步，核心是动手写代码：

  • 看教程，写代码——照着例子把每个接口都跑一遍。
  • 看文档，写代码——遇到问题查官方文档，而不是只复制粘贴。
  • 看源码，写代码——读 Vapor 和 Fluent 的源码，理解它为什么这么设计。

理论配合实践，才能比较扎实地掌握。拿起键盘就是干。

Vapor 的魅力在于「简单」：一门 Swift，前后端通吃，Codable 和 Fluent 把大量样板代码省掉，SwiftNIO 又给了你不输其它语言的并发能力。本文从环境、路由、控制器、模板、数据库、认证到部署，把一条完整的后端开发链路串了起来。但教程只是地图，真正的路况要你自己跑才知道——选一个最小可用的想法，先让它在 localhost 上跑通，再一步步加功能、接数据库、上线。写代码，永远比看代码学得快。
