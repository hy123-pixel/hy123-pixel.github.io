Vapor 从0开始：用 Swift 写后端与网站的完整教程

Vapor 是一个用纯 Swift 编写的服务端框架，底层基于苹果的非阻塞网络库 SwiftNIO。你可以用同一门语言同时包揽 iOS 客户端与后端，复用数据模型，不必在语言之间来回切换。本文从环境搭建讲起，依次覆盖第一个路由、数据库增删改查、网页渲染、用户登录与上线部署，带你把一个真实的 Vapor 应用完整跑通。

版本说明：本文内容整理自 vapor.jokerhub.cn 的《Vapor 大型教程》，示例代码主要对应 Vapor 3（SwiftNIO 时代），其中路由片段也出现了 Vapor 4 风格的写法（原始教程如此）。Vapor 目前主版本为 4，API 有变化（如用 Application 取代 router/services、异步改用 async/await），但核心概念完全一致。正式项目请以你安装的 Vapor 版本官方文档为准，本文侧重讲清思路。

一、什么是 Vapor

Vapor 是一个用 Swift 语言 编写的开源框架，底层基于苹果的 SwiftNIO 库。它能用来构建两大类应用：后端服务与 Web 网页。

2016 年 1 月，Tanner Nelson 启动了 Vapor 项目，随后 Logan Wright 也加入进来。由于 Vapor 大量运用 Swift 风格的 API 与语言特性，很快在 GitHub 上成长为流行的服务端 Swift 框架；随着 Swift 开源，它又被并入 Swift Server Group，成为苹果官方支持的服务端开发框架。

它主要由几个组件构成：

  • Leaf：用于开发前端页面的模板语言，负责把数据渲染成 HTML。
  • Fluent：用 Swift 编写的对象关系映射（ORM）框架，让你直接使用 Swift 类型操作数据库，无需手写 SQL。
为什么偏偏选 Vapor？作者给出的理由是：官网文档简洁、框架用纯 Swift 实现、社区活跃，而且项目规模不大——对于只想要基础功能的开发者来说刚刚好。简单，本来就容易让人喜欢。

二、为什么用 Swift 写服务端

许多服务端语言是解释型的，而 Swift 是编译型语言。用 Swift 做服务端开发，有几个相当实在的好处：

  • 强静态类型：编译期就能拦截大量类型错误，降低运行期崩溃的概率。
  • 编译型语言：执行性能通常优于解释型语言。
  • 前后端同一门语言：iOS 开发用 Swift，Vapor 也用 Swift，编写服务端和客户端时可复用同一套数据层模型，省去语言切换的成本，也便于向全栈拓展。
  • Codable 协议：Vapor 大量使用 Codable，可显著减少数据在「模型 ↔ 数据库 / 接口」之间做格式转换所需的样板代码。
  • 非阻塞架构：Vapor 借助 SwiftNIO 实现了完全非阻塞的架构。在阻塞式架构中，若某次请求的中间处理很耗时，响应就会被拖慢；改用多线程又会带来明显的线程切换开销。非阻塞架构则不同：若一个请求暂时无法立即返回，会被先挂起，这段时间仍可处理其它请求。

三、搭建开发环境

Vapor 的开发环境主要搭建在 macOS 与 Ubuntu 两个平台上。核心前提是先装好 Swift（Vapor 4 要求 Swift 5.2 及以上）。

macOS

借助 Xcode 这个 IDE 开发最为顺手，因为它内置了 Swift 环境。先确认一下版本：

swift --version

接着安装 Homebrew 包管理器，再用它来安装 Vapor 开发工具：

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install vapor

验证是否安装成功：

vapor --help

Ubuntu

Ubuntu 上目前还没有对 Swift 支持特别完善的 IDE，可以走两条路：一是前往 Swift 官网 按官方指引下载工具链；二是从源码安装 Vapor 工具箱：

git clone https://github.com/vapor/toolbox.git
cd toolbox
git checkout <desired version>
make install

日常开发可在 Visual Studio Code 中安装 sswg.swift-lang 插件，也可以用 Vim。完成上述步骤后，Vapor 的开发环境就搭建好了。

小技巧：在 macOS 上，进入 Vapor 项目根目录运行 vapor xcode（或 open Package.swift），即可用 Xcode 打开整个工程，进行开发、运行与调试。

四、第一个项目：Hello Vapor

环境就绪后，先用工具箱创建一个模板工程：

vapor new HelloVapor

进入目录并打开 Xcode：

cd HelloVapor
vapor xcode

运行方式有两种：在命令行中执行 vapor run，或直接在 Xcode 里点运行。项目启动后默认监听 localhost:8080。真正建立「请求 URL ↔ 处理函数」对应关系的，是工程中的 routes.swift 文件。

五、路由（Route）到底是什么

当浏览器向服务器发起请求时，服务器需要知道「该调用哪段代码来处理」。我们把客户请求（通常是一个 URL）和应用程序针对该请求进行处理的代码逻辑（通常是一个函数）之间的对应关系称为 route（路由）。routes.swift 的作用，正是建立这种对应关系。

下面在 routes.swift 中添加几个 GET 路由：

import Vapor

func routes(_ app: Application) throws {
    app.get { req in
        return "It works!"
    }
    app.get("hello") { req -> String in
        return "Hello, world!"
    }
    app.get("hello", ":name") { req -> String in
        guard let name = req.parameters.get("name", as: String.self) else {
            return "\(HTTPStatus.notFound)"
        }
        return "Hello, \(name)"
    }
}

这三个路由分别匹配以下路径：

  • / → 返回 It works!
  • /hello → 返回 Hello, world!
  • /hello/小明 → :name 是命名占位符，会取出路径中的值，返回 Hello, 小明
如果你在 Linux 上开发，可以用自己喜欢的编辑器修改文件，再借助命令行 swift build 与 vapor run 编译运行；在 Mac 上则直接用 Xcode 开发更省心。

六、用控制器组织路由

随着项目变大，一条条手写 router 既难写也难维护。Web 开发中流行的做法是 MVC：数据库中的数据结构是 Model（模型），展示给用户的 HTML 是 View（视图），控制数据如何呈现到页面的逻辑是 Controller（控制器）。Vapor 用控制器把零散的路由组织成一个个独立模块。

控制器继承自 RouteCollection，在 boot() 中注册自己的路由，routes.swift 只负责把控制器挂载上去：

import Vapor

public func routes(_ router: Router) throws {
    let acronymsController = AcronymsController()
    try router.register(collection: acronymsController)
}

控制器本体则把一组相关路由收拢到一起：

import Vapor
import Fluent

struct AcronymsController: RouteCollection {
    func boot(router: Router) throws {
        router.post("api", "acronyms", use: createHandler)
    }
    func createHandler(_ req: Request) throws -> Future<Acronym> {
        return try req.content.decode(Acronym.self)
            .flatMap(to: Acronym.self) { (acronym) in
                return acronym.save(on: req)
            }
    }
}

当控制器里的多条路由共享同一个前缀（比如都挂在 api/acronyms 下）时，用 RouteGroup 更省事，可避免每条都写完整路径：

func boot(router: Router) throws {
    let routeGroup = router.grouped("api", "acronyms")
    routeGroup.post(use: createHandler)
    routeGroup.get(use: getAllHandler)
    routeGroup.get(Acronym.parameter, use: getHandler)
}

七、用 Leaf 渲染网页

前面的接口返回的都是纯文本或 JSON。如果要给用户看真正的网页，Vapor 提供了 Leaf 模板语言：它允许你向页面传入变量，动态生成最终 HTML，还能在页面之间复用代码块。

先在 Package.swift 中加入 Leaf 依赖，然后新建 Resources/Views 目录来存放模板。接着写一个专门返回网页的控制器：

import Vapor
import Leaf

struct WebsiteController: RouteCollection {
    func boot(router: Router) throws {
        router.get(use: indexHandler)
    }
    func indexHandler(_ req: Request) throws -> Future<View> {
        return try req.view().render("index")
    }
}

在 routes.swift 里注册这个控制器，并在 configure.swift 中把 Leaf 配置为一种服务：

try services.register(LeafProvider())
config.prefer(LeafRenderer.self, for: ViewRenderer.self)

Leaf 通过 #(arg) 的方式把参数注入模板。在控制器中，通常会定义一个遵循 Encodable 的上下文结构体来传递数据：

struct IndexContext: Encodable {
    let title: String
}

对应的 Resources/Views/index.leaf 模板中的写法如下：

<title>#(title) | Acronyms</title>

八、数据库与 Fluent ORM

Vapor 原生提供三种数据库驱动：SQLite、MySQL、PostgreSQL。数据库分为关系型（SQL）与非关系型（NoSQL）两类，而 Vapor 目前仅支持关系型数据库。

  • SQLite：基于文件的轻量关系型数据库，适合原型与测试，但不适合高频写入或跨服务器场景。
  • MySQL：常见于 LAMP 技术栈，易用且被多数云厂商支持。
  • PostgreSQL：面向企业级应用的开源关系库，以扩展性与标准化为核心目标。

在本地用 Docker 跑 MySQL / PostgreSQL 非常方便（它不同于虚拟机，更轻量）。为了尽快跑通，开发阶段推荐先用 SQLite（数据直接存放在本地文件中）。只需在 configure.swift 中注册即可：

try services.register(FluentSQLiteProvider())

let sqlite = try SQLiteDatabase(storage: .file(path: "db.sqlite"))
var databases = DatabasesConfig()
databases.add(database: sqlite, as: .sqlite)
services.register(databases)

var migrations = MigrationConfig()
migrations.add(model: Acronym.self, database: .sqlite)
services.register(migrations)
仅使用 SQLite 就能极大简化数据库配置，非常适合原型开发阶段；等到要上生产环境时，再换成 MySQL 或 PostgreSQL（配合 Docker）即可。

九、RESTful CRUD 接口

RESTful API 的思路是：用一个 URL 对应一个数据模型，再配合不同的 HTTP 方法（Method）来执行对应的增删改查（CRUD）操作。以 /api/acronyms 为例：

操作方法 + URL含义
Create 新增POST /api/acronyms创建一个新的缩略语
Retrieve 列表GET /api/acronyms获取所有缩略语
Retrieve 详情GET /api/acronyms/<ID>获取指定 ID 的缩略语
Update 更新PUT /api/acronyms/<ID>更新指定 ID 的缩略语
Delete 删除DELETE /api/acronyms/<ID>删除指定 ID 的缩略语

新增（Create）就是把请求体解码成模型后保存：

router.post("api", "acronyms") { (req) -> Future<Acronym> in
    return try req.content.decode(Acronym.self)
        .flatMap(to: Acronym.self) { (acronym) in
            return acronym.save(on: req)
        }
}

按 ID 查询（Retrieve）需要数据模型遵循 Parameter 协议：

extension Acronym: Parameter {}

router.get("api", "acronyms", Acronym.parameter) { (req) -> Future<Acronym> in
    return try req.parameters.next(Acronym.self)
}

更新（Update）则是先取出旧记录，合并新字段后再保存：

router.put("api", "acronyms", Acronym.parameter) { (req) -> Future<Acronym> in
    return try flatMap(to: Acronym.self,
                       req.parameters.next(Acronym.self),
                       req.content.decode(Acronym.self)) { (acronym, update) in
        acronym.name = update.name
        // ...合并其它字段
        return acronym.save(on: req)
    }
}

十、用户认证

认证（Authentication）是验证「你是谁」的过程，与授权（Authorization）「你能做什么」不同。最常见的做法是使用「用户名 + 密码」组合。

密码绝不能以明文存储。Vapor 提供了工业级的 BCrypt 算法对密码做哈希：哈希是单向的，几乎不可能从哈希值反推出明文，而且 BCrypt 会自动加盐。因此在创建用户时，要先做哈希再存储：

import Crypto

func createHandler(_ req: Request, user: User) throws -> Future<User> {
    user.password = try BCrypt.hash(user.password)
    return user.save(on: req)
}

此外，登录时需要通过「用户名 + 密码」唯一定位用户，所以用户名必须唯一。可在迁移中加上唯一约束：

extension User: Migration {
    static func prepare(on conn: PostgreSQLConnection) -> Future<Void> {
        return Database.create(self, on: conn) { (builder) in
            try addProperties(to: builder)
            builder.unique(on: \.username)
        }
    }
}
新增字段或约束后，需要重置一次数据库让变动生效（在 Xcode 的 Scheme 设置里加上运行时参数即可）。

十一、部署到自己的云服务器

除了官方的 Vapor Cloud，你也能把项目部署到自己购买的云服务器上。思路是：在 Ubuntu 上安装 Docker，用 Docker 启动一个数据库容器，再运行 Vapor 应用。

docker run --name postgres \
  -e POSTGRES_DB=vapor \
  -e POSTGRES_USER=vapor \
  -e POSTGRES_PASSWORD=password \
  -p 5432:5432 \
  -d postgres

然后启动应用，并让它监听所有网卡：

vapor run --hostname=0.0.0.0 --port=8080

最后别忘了在云服务器控制台开放端口、配置域名解析，并用 nginx 做端口转发（把 80/443 转发到 8080）。这样外界就能通过域名访问你的 API 了。

十二、怎么把 Vapor 学扎实

原教程作者总结的学习路径只有三步，核心就是动手写代码：

  • 看教程，写代码——照着示例把每个接口都跑一遍。
  • 看文档，写代码——遇到问题查阅官方文档，而不是只会复制粘贴。
  • 看源码，写代码——读 Vapor 和 Fluent 的源码，理解它为什么这么设计。

理论结合实践，才能真正学得扎实。拿起键盘就是干。

Vapor 的魅力在于「简单」：一门 Swift，前后端通吃，Codable 和 Fluent 帮你省掉大量样板代码，SwiftNIO 又给了你并不输其它语言的并发能力。本文从环境、路由、控制器、模板、数据库、认证到部署，把一条完整的后端开发链路串了起来。不过教程只是地图，真正的路况还得你亲自跑才知道——选一个最小可用的点子，先让它在 localhost 上跑通，再一步步加功能、接数据库、上线。写代码，永远比看代码学得快。
